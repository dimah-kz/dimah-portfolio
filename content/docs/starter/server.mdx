---
title: Server-first
description: How dimah-starter reads and writes. Sessions stay on the server, and a write shows up in the same response.
---

dimah-starter uses Next.js 16 the way that version is shaped: Cache Components, Partial Prefetching, and Server Actions. `cacheComponents` and `partialPrefetching` are on in `apps/web/next.config.ts`.

A link prefetches the route's App Shell. The signed-in parts stream in after navigation. Lists and profile reads are cache entries tagged per user or organization. A Server Action expires the tags it changed with `updateTag`, so the person who acted sees fresh data in the same response. There is no `router.refresh()` and no client cache to invalidate.

## A read

A page checks the session and the permission, then reads through a `'use cache'` function. The cached function receives ids. It does not call `headers()` or `cookies()`, because a cached result is shared between requests.

This is the members list, trimmed the same way the repository README trims it:

```ts
export async function getOrganizationMembersPage(query) {
  const { organizationId } = await requireOrganizationManager();
  return getCachedPage(organizationId, query);
}

async function getCachedPage(organizationId, query) {
  "use cache";
  cacheLife("minutes");
  cacheTag(tags.organizationMembersById(organizationId));
  return db.select().from(member);
}
```

`requireOrganizationManager` runs on every request. The layout is not the only gate. The same rule is `requireDashboardSession` for a signed-in page and `requirePlatformAdmin` for the platform admin.

## A write

Writes live in `apps/web/src/app/action/`, one file per action, mirroring the route. Auth, organizations, and admin go through `auth.api`. Product data goes through `createRouterClient` from `@repo/api`. Route Handlers are not added for writes. `app/api/` only mounts Better Auth, oRPC, and upload tickets.

```ts
export async function removeOrganizationMemberAction(input) {
  await auth.api.removeMember({ headers: await headers(), body });
  updateTag(tags.organizationMembersById(input.organizationId));
}
```

`updateTag` is what the actor sees next. `revalidateTag(tag, "max")` is for everyone else's view. Tags come from that segment's `cache-tags.ts`.

Sessions are never placed inside `'use cache'`. A cached session would serve one person's data to another.

The rules for what to cache, which tag to expire, and why, are in [docs/agents/nextjs.md](https://github.com/dimah-kz/dimah-starter/blob/main/docs/agents/nextjs.md) in the repository.
