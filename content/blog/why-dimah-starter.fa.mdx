بیشتر استارترهای Next.js از مرورگر شروع می‌کنند. یک SDK احراز هویت، یک کتابخانه کوئری و چند ویجت تحویل می‌گیرید و بعد سازمان‌ها، دسترسی‌ها و باطل‌کردن کش به عهده خودتان است. [dimah-starter](https://starter.dimah.dev) را برعکس ساختم: نشست‌ها، دسترسی‌ها و داده در اختیار سرور است و مرورگر فقط چیزی را که دریافت می‌کند نمایش می‌دهد.

## خواندن

هر صفحه یک Server Component است. در هر درخواست، نشست و دسترسی را بررسی می‌کند و بعد داده را از یک تابع `'use cache'` می‌خواند که برای همان کاربر یا سازمان برچسب خورده است:

```ts
export async function getOrganizationMembersPage(query) {
  const { organizationId } = await requireOrganizationManager();
  return getCachedPage(organizationId, query);
}

async function getCachedPage(organizationId, query) {
  "use cache";
  cacheLife("minutes");
  cacheTag(tags.organizationMembersById(organizationId));
  return db.select().from(member); // …
}
```

دو قاعده این روش را امن نگه می‌دارد. بررسی دسترسی روی خود خواندن انجام می‌شود، نه فقط در layout؛ چون دروازه‌ای در layout داده‌های صفحه را از پاسخ آن بیرون نگه نمی‌دارد. و تابع کش‌شده هیچ‌وقت به `headers()` یا `cookies()` دست نمی‌زند: نشستِ کش‌شده بین درخواست‌ها مشترک می‌شود، پس نشست‌ها هرگز کش نمی‌شوند.

## نوشتن

هر تغییر داده یک Server Action است. برای کاربران، سازمان‌ها و نقش‌ها Better Auth را صدا می‌زند و برای منطق محصول روتر oRPC را، و بعد دقیقاً همان چیزی را منقضی می‌کند که تغییر داده است:

```ts
export async function removeOrganizationMemberAction(input) {
  await auth.api.removeMember({ headers: await headers(), body });
  updateTag(tags.organizationMembersById(input.organizationId));
}
```

به لطف `updateTag`، کسی که فرم را فرستاده داده تازه را در همان پاسخ می‌بیند. نه کلاینت احراز هویتی هست که hydrate شود و نه کش کوئری‌ای که باید باطل شود.

## چندمستأجری از اجرای اول

سازمان‌ها، دعوت با ایمیل و نقش‌های owner، admin و member از اولین `pnpm dev` وجود دارند. فارسی و انگلیسی هم همین‌طور: جهت یک بار روی سند تنظیم می‌شود و چیدمان، بدون وصله‌کاری روی تک‌تک کامپوننت‌ها، برای راست‌به‌چپ قرینه می‌شود.

## چه چیزهایی کنار گذاشته شده

پرداخت، CMS و آنالیتیکس در استارتر نیستند. سرویسی را انتخاب می‌کنید که با محصولتان جور است، نه اینکه سرویسی را که به کارتان نمی‌آید حذف کنید.
