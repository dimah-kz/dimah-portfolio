Most Next.js starters begin in the browser. You get an auth SDK, a query library, and a set of widgets, and then organizations, permissions, and cache invalidation are yours to figure out. I built [dimah-starter](https://starter.dimah.dev) the other way around: the server owns sessions, permissions, and data, and the browser renders what it is sent.

## Reads

A page is a Server Component. It checks the session and the permission on every request, then reads through a `'use cache'` function tagged for that user or organization:

```ts
export async function getOrganizationMembersPage(query) {
  const { organizationId } = await requireOrganizationManager();
  return getCachedPage(organizationId, query);
}

async function getCachedPage(organizationId, query) {
  "use cache";
  cacheLife("minutes");
  cacheTag(tags.organizationMembersById(organizationId));
  return db.select().from(member); // …
}
```

Two rules keep this safe. The permission check runs on the read itself, not only in a layout, because a layout gate does not keep a page's data out of its response. And the cached function never touches `headers()` or `cookies()`: a cached session would be shared between requests, so sessions are never cached.

## Writes

Every write is a Server Action. It calls Better Auth for users, organizations, and roles, or the oRPC router for product logic, and then expires exactly what it changed:

```ts
export async function removeOrganizationMemberAction(input) {
  await auth.api.removeMember({ headers: await headers(), body });
  updateTag(tags.organizationMembersById(input.organizationId));
}
```

Because of `updateTag`, the person who submitted the form sees fresh data in the same response. There is no auth client to hydrate and no query cache to invalidate.

## Multi-tenant from the first run

Organizations, email invitations, and the owner, admin, and member roles exist from the first `pnpm dev`. So do English and Persian: the direction is set once on the document, and the layout mirrors for right-to-left without patches on individual components.

## What is left out

Billing, a CMS, and analytics are not included. You pick the provider that fits your product, instead of removing one that doesn't.
